## Challenge 3: Secret rotation

Demonstrate zero-downtime secret rotation using a Deployment with rolling updates.

Requirements:
- Create an initial Secret named rotating-secret with:
    - api-key: "initial-key-v1"
    - db-password: "initial-pass-v1"

- Create a Deployment named secret-rotation-app that:
    - Runs 3 replicas
    - Uses busybox:1.37 image
    - Has a RollingUpdate strategy with maxSurge: 1 and maxUnavailable: 1
    - Includes a pod template annotation: secret-version: "v1"
    - Loads the secrets as environment variables: API_KEY from secret key api-key, DB_PASS from secret key db-password
    - Has the container print API Key first 10 chars: <first-10-chars>... and DB Pass first 10 chars: <first-10-chars>... on startup
    - Then runs a loop that increments a request counter and prints [timestamp] Serving request <count> with API key <first-10-chars>... every 5 seconds
    - Includes a readiness probe that verifies both API_KEY and DB_PASS are set

- Monitor the application:
    - Watch pods in one terminal: kubectl get pods -l app=rotation-demo -w
    - Watch availability in another: kubectl get deployment secret-rotation-app -w (the AVAILABLE column)
    - Watch logs in a third: kubectl logs -f -l app=rotation-demo --prefix=true --timestamps=true. This only follows the Pods that exist when you start it, so run it again after the rollout to see the new ones.

- Rotate the secret by:
    - Creating a new version with api-key "rotated-key-v2" and db-password "rotated-pass-v2"
    - Applying the updated secret
    - Triggering a rolling update by patching the deployment's pod annotation to secret-version: "v2"

- Observe the zero-downtime rotation:
    - Old pods continue serving with old secrets
    - New pods start with new secrets
    - One pod at a time is replaced (due to maxUnavailable: 1)
    - The application keeps serving throughout: AVAILABLE never drops below 2
    - Eventually all pods use the new secrets

Success Criteria:
- Initial deployment runs with 3 replicas using v1 secrets
- During rotation, at least 2 pods are always available
- New pods start with v2 secrets while old pods still use v1
- Old pods keep logging "Serving request" lines until their replacements are Ready
- After rotation completes, all pods use v2 secrets
- Secrets are partially shown (first 10 chars) but never fully exposed
